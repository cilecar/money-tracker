# Долги: разделение покупок и «за меня заплатили»

Дата: 2026-11-01. Статус: дизайн согласован, ждёт ревью спецификации.

## Цель

Учитывать два сценария:

1. **«Я заплатил — мне скидываются».** Покупка с моего счёта, часть суммы должны вернуть один или несколько человек.
2. **«За меня заплатили — я должен».** Покупку (мою долю) оплатил другой человек, с моих счетов ничего не списано.

Критерии успеха:

- Аналитика, бюджеты и итоги месяца показывают **только мою долю** — сразу в день покупки, не дожидаясь погашения.
- Баланс счёта всегда равен реальному движению денег: расход списывает полную сумму, погашения двигают баланс.
- Каждый долг закрывается **отдельно** (своим счётом, датой и суммой), целиком.

Не входит в первую версию: займы деньгами без покупки, частичное погашение, смешанная оплата одной
покупки мной и другом, напоминания, неттинг «рассчитались по сальдо», изменения CSV-экспорта.

## Подход

Долг — поправка к расходам по образцу возвратов (`Refund.asNegativeExpense()`). Существующие таблицы
не меняются: добавляются три новые. Вариант «расход без счёта» (nullable `Expense.accountId`) отвергнут:
`accountId` используется в 22 файлах (балансы, фильтры, автозахват, повторяющиеся, CSV).

## 1. Модель данных (БД v5)

### Таблица `person`

| колонка | тип | примечание |
|---|---|---|
| `id` | PK autoincrement | |
| `name` | TEXT NOT NULL | обрезанное, непустое |
| `archived` | INTEGER NOT NULL | человек с историей не удаляется, а архивируется |
| `sort_order` | INTEGER NOT NULL | |

Удаление человека разрешено только без долгов (FK `RESTRICT` из обеих таблиц ниже).

### Таблица `expense_share` — «мне должны»

| колонка | тип | примечание |
|---|---|---|
| `id` | PK | |
| `expense_id` | FK → `expense`, `ON DELETE CASCADE` | |
| `person_id` | FK → `person`, `RESTRICT` | |
| `amount_minor` | INTEGER NOT NULL | в валюте расхода, > 0 |
| `settled_at`, `settled_local_date`, `settle_account_id`, `settle_amount_minor` | nullable | погашение, см. ниже |
| `created_at`, `updated_at` | | |

Индексы: уникальный `(expense_id, person_id)`, `person_id`, `settle_account_id`, `settled_local_date`.
Валюту, категорию, дату, счёт и снапшот курса доля **не хранит** — берёт у расхода.

### Таблица `paid_for_me` — «я должен»

Расход без счёта: `id`, `person_id` (FK `RESTRICT`), `amount_minor`, `currency`, `category_id`
(FK → `category`, `RESTRICT`), `occurred_at`, `local_date`, `comment`, колонки снапшота курса и
пересчитанных сумм как у `refund` (`rate_rsd_per_eur`, `rate_rub_per_eur`, `rate_usdt_per_eur`,
`rate_date`, `rsd_minor`, `eur_minor`, `rub_minor`), четыре колонки погашения, `created_at`, `updated_at`.
Индексы: `person_id`, `local_date`, `category_id`, `rate_date`, `settle_account_id`, `settled_local_date`.

### Погашение

Пять колонок в обеих таблицах: `settled_at`, `settled_local_date`, `settle_account_id`
(FK → `account`, `RESTRICT`), `settle_amount_minor` — **в валюте счёта погашения**, > 0, и `settle_currency`
(дублируется из счёта, как у перевода: смена валюты счёта не исказит историю).
Все пять либо NULL (долг открыт), либо заполнены. Разница курсов при погашении в другой валюте
нигде не учитывается: долг закрывается целиком.

### Домен (`:domain`)

- `Person(id, name, archived, sortOrder)`.
- `Settlement(accountId, amount: Money /* валюта счёта */, occurredAt, localDate)`.
- `ExpenseShare(id, expenseId, personId, amount: Money /* валюта расхода */, settlement: Settlement?)`.
- `PaidForMe(... : RatedAmount, settlement: Settlement?)` с `create`, `withOccurredAt`, `withAmount`,
  `withRates` по образцу `Refund`.

Инварианты (проверяются в use case сохранения расхода):

- каждая доля > 0 и в валюте расхода; сумма долей ≤ суммы расхода (моя доля может быть 0);
- один человек — одна доля в расходе;
- смена валюты расхода с долями требует заново ввести доли (UI сбрасывает несохранённые; погашенная доля блокирует смену валюты);
- уменьшение суммы расхода ниже суммы долей — ошибка валидации;
- погашенную долю нельзя изменить или удалить, пока не отменено погашение.

`splitEqually(total, people)`: делит на `people + 1` (я + выбранные) в минорных единицах, каждому `floor`,
остаток — мне. 1000.00 на троих: 333.33 / 333.33 / мне 333.34.

### Удаление

- Расход с долями: доли удаляются каскадом («Отменить» возвращает их). Расход с погашенной долей
  удалить нельзя — как и погашенную запись «в долг»: сначала отменить погашение в карточке человека,
  иначе деньги молча ушли бы из баланса счёта.
- «Отменить» после удаления расхода: `DeletedExpense` запоминает доли (с погашениями), `restore` возвращает их с теми же id.
- Категория: удаление с переносом переносит и `paid_for_me`; счётчик использований их учитывает.
- Счёт: проверки «есть операции» учитывают `settle_account_id`; слияние счетов переносит и его.

### Миграция и бэкап

- `Migration4To5`: только `CREATE TABLE` / `CREATE INDEX` для трёх таблиц. Схема `app/schemas/.../5.json`;
  после смены версии — `./gradlew clean` и сборка `--no-build-cache`, проверить, что 1–4.json не изменились.
- `BackupDto`: списки `persons`, `expenseShares`, `paidForMe` (с дефолтом `emptyList()` для старых бэкапов).

## 2. Аналитика, бюджеты, балансы

### Траты

Везде, где считаются траты — `ObserveAnalyticsUseCase`, `BudgetUseCases` (и уведомления бюджетов),
`ObserveMonthSummaryUseCase` (включая «Осталось до конца месяца»), итог отфильтрованного списка, —
кроме расходов и возвратов добавляются:

- `ExpenseShare.asNegativeExpense(expense)` — минус доля с **датой, категорией, счётом и курсом исходного
  расхода** (`expense.rates.convertAll(share.amount)`);
- `PaidForMe.asExpense()` — плюс сумма со своими датой, категорией и курсом.

Доля учитывается в день покупки, а не погашения (в отличие от возврата): договорённость «трачу только
1000» известна сразу. Пример: ужин 3000, доли 2×1000 → «Рестораны» за этот день +1000.

### Разбивка по счетам

Доля вычитается из среза счёта расхода. `PaidForMe` — отдельный срез «Оплатили другие» (без счёта).
Фильтр списка по счёту исключает `PaidForMe`; доли расходов на выбранном счёте учитываются.

### Балансы

Только погашения меняют баланс. В SQL баланса (`AccountDao`):

- `+ SUM(expense_share.settle_amount_minor)` где `settle_account_id = a.id` и `settled_local_date >= a.opening_date`;
- `− SUM(paid_for_me.settle_amount_minor)` с теми же условиями.

Сумма погашения в валюте счёта — `CASE`-конвертация и `unconverted` не нужны.
Итог по счетам долги не включает.

### Курсы

`FillPendingRatesUseCase` дозаполняет снапшот у `paid_for_me`. Доли курс не хранят.

## 3. Интерфейс

### Форма расхода

Под чипами счетов — строка «Разделить» → нижняя панель: чипы людей + «+ Новый» (ввод имени),
поле суммы у каждого выбранного, кнопка «Поровну», итог «Моя доля: X». При превышении суммы
сохранить нельзя. Свёрнутая строка: «Петя, Вася · моя доля 1000». Погашенные доли в панели только
для чтения. Расход и доли сохраняются в одной транзакции. Автозахват не меняется — делить можно при
редактировании захваченного расхода.

### «В долг»

`NewOperationKind.DEBT` — четвёртая вкладка «В долг». Отдельный экран `PaidForMeEditScreen` на
`OperationParts` (`AmountHeader`, категория, `DateTimeRow`, `CommentField`) с чипами людей вместо
счетов. Маршрут `PaidForMeEditRoute(id)`.

### Экран «Долги» (пункт в «Ещё»)

Сверху «Мне должны X · Я должен Y» в валюте отображения по текущим курсам. Ниже — люди с
открытыми долгами и сальдо по каждому (информационно). Маршрут `DebtsRoute`.

### Карточка человека

`PersonDebtsRoute(personId)`. Открытые долги: «Ужин, 12 окт — должен тебе 1000 RSD» /
«Кино — ты должен 400 RSD», у каждого «Погашено» → диалог: счёт (по умолчанию — счёт расхода; для
«в долг» — счёт по умолчанию), сумма в валюте счёта (та же при совпадении валют, иначе по текущему
курсу), дата (сегодня). Свёрнутый раздел «Закрытые» с действием «Отменить погашение».
Меню: «Переименовать», «В архив».

### Список операций

- Расход с долями: крупно полная сумма, второй строкой «моя доля 1000». Итог дня — по долям.
- `PaidForMe`: строка «Петя заплатил · Кино 400»; тап — форма, свайп — удаление.
- Погашения: строка в день погашения «Петя вернул 1000 → Карта» / «Отдал Пете 400 ← Карта»;
  тап — карточка человека.
- Фильтр по видам: новый `OperationKind.DEBT` (PaidForMe и погашения).
