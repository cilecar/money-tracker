# Чеки и цены — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** скан QR сербского фискального чека → чек привязан к расходу, позиции сохранены → вкладка «Цены» с историей цен по продуктам и сравнением сетей.

**Architecture:** чистая логика (разбор ссылки `vl`, названий позиций, текста чека, подбор кандидатов, серии цен) живёт в `:domain` в пакете `app.moneytracker.domain.receipt`; сеть (`SufClient`), Room (6 таблиц, БД v6), WorkManager и Compose-экраны — в `:app`. Домен видит сеть через интерфейс `ReceiptSource`, фоновую догрузку — через `ReceiptSyncScheduler`.

**Tech Stack:** Kotlin, Room 2.8, Hilt, OkHttp (из Retrofit) + kotlinx.serialization, WorkManager, Compose M3, vico 3, Google Code Scanner (`play-services-code-scanner`).

**Spec:** `docs/superpowers/specs/2026-11-05-receipts-design.md`

## Global Constraints

- Gradle на JDK 21; `:domain` — чистый Kotlin/JVM, тесты — JUnit без Robolectric; `:app` — Robolectric.
- Деньги — `Long` минорных единиц (пары); валюта чека всегда `CurrencyCode.RSD`. Количество — `Long` в тысячных (0.534 кг → 534, 1 шт → 1000). Ни `Double`, ни `Float` в моделях и БД.
- Перевод чисел из JSON сервера: `BigDecimal(value.toString()).movePointRight(n).setScale(0, RoundingMode.HALF_UP).longValueExact()` (n = 2 для денег, 3 для количества).
- Запросы только на `https://suf.purs.gov.rs`.
- Тексты UI — на русском, в `app/src/main/res/values/strings.xml`.
- Логи — `Log.w`, не `Log.d` (на телефоне пользователя `Log.d` отбрасывается).
- После смены версии БД: `./gradlew clean`, затем сборка с `--no-build-cache`; `git diff app/schemas/1.json … 5.json` должен быть пустым, `6.json` — новый.
- Проверка после каждого этапа: `./gradlew assembleDebug :domain:test :app:testDebugUnitTest`. Таймауты `runTest` в `DataTransferTest`/`RemoteRatesDataSourceTest` при высокой нагрузке машины — известный флейк, перезапустить.
- Работа в ветке `feature/receipts`; коммит после каждой задачи, **без push** (пуш — после всей реализации, по команде пользователя). Сообщения коммитов — на русском, с трейлерами `Co-Authored-By`/`Claude-Session` из системных инструкций.
- После этапов 3 и 4 — стоп: пользователь проверяет на телефоне (`./gradlew :app:installDebug`, приложение `app.moneytracker.debug`).

## Review Focus

1. **`+` в `vl`.** Сканеры и «Поделиться» отдают ссылку то с `%2B`, то с сырым `+`, а наивный URL-декодер превращает `+` в пробел и ломает base64. Ожидание: обе формы разбираются одинаково. Тест — в задаче 1.
2. **Дробный вес из JSON.** `0.534` как `Double` даёт `533.999…`; ожидание: ровно 534 тысячных и 416,51 сумма. Тест — в задаче 6.
3. **Один артикул дважды в чеке** (у Lidl «Bolonjeze sos» ×2): две позиции, один артикул, без нарушения UNIQUE. Тест — в задаче 5.
4. **Повторная загрузка того же чека** (ручное «Повторить» после FAILED или воркер после частичного ответа): позиции заменяются, а не дублируются; артикулы и продукты не плодятся. Тест — в задаче 5.
5. **Удаление расхода с чеком и «Отменить»**: чек снова прикреплён к восстановленному расходу. Тест — в задаче 5.
